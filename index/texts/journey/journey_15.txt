## Chapter 15: Visibility, Verification, and Documentation

While navigating through the My Journey and HackTheBox sections of my site, I noticed that it wasn’t always clear which page I was currently on. To improve the user experience, I made the active link visually distinct—disabling it, greying it out, and making it unclickable. This subtle change made a big difference in helping users understand their location at a glance.

While researching other improvements, I stumbled upon websites that help verify the authenticity and safety of web domains. These included:

- FortiGuard Labs  
- CRDF Threat Center  
- Scam Adviser  
- Cloudflare  

Naturally, I decided to check my own site. Unsurprisingly, there were no results—my website had just launched, and I'm probably still its only regular visitor.

This curiosity led me to implement a basic statistics service and view counter. While I haven't added unique visitor tracking yet, it’s not a priority at the moment. Interestingly, I started seeing around 30 views per day, likely from bots or automated crawlers scanning the site.

To wrap up the 3 months' progress, I documented all the core implementations in the [GitHub Wiki](https://github.com/Chase-developer/portfolio/wiki). I also added a `README.md` to the repository itself, giving an overview of the project for anyone who stumbles upon it.

These additions don’t just improve usability—they give context, build credibility, and offer a window into the architecture behind the scenes.

---

### Key Actions:
- Improved navigation UX by greying out and disabling the current page link.
- Verified site authenticity using FortiGuard, CRDF, Scam Adviser, and Cloudflare.
- Added view counter, noticing initial traffic likely from web crawlers.
- Created GitHub Wiki detailing core implementations of the project.
- Published README.md to give a quick overview for new visitors.
