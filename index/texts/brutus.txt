## 1. Incident Overview

- Incident Type: Unauthorized SSH Brute-Force Attack" 
- Affected System: `ip-172-31-35-28`  
- Initial Detection: Multiple failed SSH login attempts recorded in system logs.  

---

## 2. Event Chronology  

### 2.1 Unauthorized SSH Login Attempt (Reconnaissance Phase)  
- Timestamp: `March 6, 2025, 06:31:31 UTC`  
- Source IP: `65.2.161.68`  
- Destination IP: `172.31.35.28`  
- Service: SSH  

#### Event Details:  
- the attacker initiated an unauthorized SSH login attempt using the invalid username "admin".  
- the request was rejected by `sshd`, suggesting an initial reconnaissance attempt.  

---

### 2.2 Brute-Force Attack Initiation  
- Timestamp: `March 6, 2025, 06:31:31 UTC`  
- Source IP: `65.2.161.68`  
- Destination IP: `172.31.35.28`  
- Service: SSH  

#### Event Details:  
- the attacker began an automated brute-force attack, making multiple connection attempts.  
- the system engaged MaxStartups throttling, limiting simultaneous connections.  
- the attack continued despite throttling, with repeated authentication failures for user "admin".  

---

### 2.3 Escalation to Root Account Targeting  
- Timestamp: `March 6, 2025, 06:31:41 - 06:31:42 UTC`  
- Source IP: `65.2.161.68`  
- Destination IP: `172.31.35.28`  
- Service: SSH  

#### Event Details:  
- the attacker shifted focus from "admin" to the root account, attempting direct authentication.  
- failed Password Attempts:  
  - Multiple password failures recorded for user "root".  
- connection drops:  
  - several connections were closed during authentication, indicating aggressive password attempts.  
- PAM authentication failures:  
  - `pam_unix` logged authentication failures for user "root", confirming unsuccessful brute-force attempts.  

---

### 2.4 Successful Infiltration  
- Timestamp: `March 6, 2025, 06:32:44 UTC`  
- Source IP: `65.2.161.68`  
- Destination IP: `172.31.35.28`  
- Service: SSH  

#### Event Details:  
- the attacker successfully authenticated using the root account.  
- a session was opened for user root `(uid=0)`, confirming full system access.  
- `systemd-logind` registered a new session for root, indicating an active shell session.  
- this marks the point of system compromise.  

---

### 2.5 Post-Exploitation Activities  
- Timestamp: `March 6, 2025, 06:34:18 - 06:39:39 UTC`  
- Source IP: `65.2.161.68`  
- Destination IP: `172.31.35.28`  

#### Event Details:  
- the attacker created a new user account named "cyberjunkie" with `UID=1002` and `GID=1002`.  
- the attacker modified `/etc/group` and `/etc/gshadow` to add the new user.  
- a password change was performed for the `cyberjunkie` user.  
- the user’s information was altered using `chfn`.  
- the attacker granted sudo privileges to `cyberjunkie`, effectively escalating privileges for future persistence.  
- possible scheduling of cron jobs, with logs showing cron sessions for `root` and `confluence` users.  
- the attacker logged out of the root account and logged in as `cyberjunkie` at `06:37:34 UTC`.  
- privilege Escalation: `cyberjunkie` used `sudo` to read `/etc/shadow`, confirming T1003 (OS Credential Dumping).  
- ingress Tool Transfer: The attacker downloaded `linper.sh` using `curl` via `sudo`, indicating T1105 (Ingress Tool Transfer) for post-exploitation enumeration.  

---

## 3. Analysis  

- the attacker escalated efforts by targeting the root account after failing with "admin".  
- the attack pattern indicates an automated tool, likely a credential stuffing attack.  
- the use of the root account suggests a more serious attempt to gain privileged access.  
- despite multiple failed attempts, the attacker remained persistent.  
- the successful authentication confirms compromise of root credentials, granting the attacker full control.  

### MITRE ATT&CK Techniques Identified:  
- T1078 (Valid Accounts): the attacker used stolen credentials for access.  
- T1098 (Account Manipulation): a new privileged user account (`cyberjunkie`) was created.  
- T1136 (Create Account): establishing persistence via account creation.  
- T1543 (Create or Modify System Process): potential cron job scheduling for backdoor access.  
- T1003 (OS Credential Dumping): attempted access to `/etc/shadow` file for credential theft.  
- T1105 (Ingress Tool Transfer): downloading `linper.sh` for potential system enumeration.  

---

## 4. Mitigation and Incident Response  

### 4.1 Immediate Mitigation Steps  
- Revoke Access: disable the `cyberjunkie` user and remove sudo privileges.  
- Change Credentials: reset root and all user passwords.  
- Kill Active Sessions: terminate all active SSH sessions from `65.2.161.68`.  
- Update Firewall Rules: block the attacker’s IP and restrict SSH access.  
- Check System Integrity: run malware and rootkit scans.  

---

### 4.2 Long-Term Security Measures  
- Implement Multi-Factor Authentication (MFA) for SSH.  
- Limit SSH Access: restrict SSH to trusted IPs via firewall rules.  
- Enhance Logging & Monitoring: enable alerts for multiple failed logins.  
- Use SSH Key-Based Authentication: disable password authentication.  
- Regularly Update Software: patch vulnerabilities and enforce system updates.  

---

### 4.3 Incident Response Actions  
- Forensic Investigation: preserve logs and analyze indicators of compromise.  
- Threat Intelligence Sharing: report attack indicators to security databases.  
- Review Security Policies: strengthen access controls and security policies.  
- Employee Security Training: educate users on phishing and credential security.
