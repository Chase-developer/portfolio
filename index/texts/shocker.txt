## Red Team Penetration Testing Report

### Overview
This report documents the security weaknesses identified during the assessment of `shocker.htb`. 
The engagement led to privilege escalation from an initial foothold to full domain compromise.

---

## Findings and Recommendations

### Finding 1: **Open Network Ports and Services**
#### Identified Ports:
```bash
PORT     STATE SERVICE        VERSION
80/tcp   open  http    Apache httpd 2.4.18 ((Ubuntu))
2222/tcp open  ssh     OpenSSH 7.2p2 Ubuntu 4ubuntu2.2 (Ubuntu Linux; protocol 2.0)
```

#### Risk Rating:
- Medium: Publicly accessible HTTP server could be susceptible to common web vulnerabilities such as cross-site scripting (XSS) or injection attacks.
- High: Exposed SSH service could be leveraged for brute force or key-based attacks.

#### Recommendations:
- Remove or obfuscate the server banner to reduce exposure of version information.
- Implement SSL/TLS for encrypted communication.
- Enforce strong authentication methods and disable root login.
- Restrict SSH access to trusted IP addresses using firewall rules.
- Regularly update OpenSSH to mitigate known vulnerabilities.
- Update the Linux kernel and associated packages to the latest stable versions.
- Implement network segmentation to restrict access to critical services.
---

### Finding 2: **Vulnerable CGI Script**
#### Identified Endpoint:
```bash
http://shocker.htb/cgi-bin/user.sh
```

#### Observation:
- The gobuster scan revealed a publicly accessible CGI script: user.sh
- The script is likely executable and could be exploited for remote code execution (RCE) vulnerabilities.
- Metasploit has an available module specifically designed to exploit this vulnerability, which significantly increases the risk of exploitation by attackers.

#### Risk Rating:
- Critical: This vulnerability could allow an attacker to execute arbitrary commands on the host server, potentially gaining unauthorized access to sensitive data or taking full control of the system.

#### Recommendations:
- Immediately restrict access to the CGI directory using web server configuration settings or firewall rules.
- Audit the script (user.sh) for vulnerabilities and remove or replace it if not essential.
- Update the web server to the latest secure version and ensure secure scripting practices are followed.
- Perform regular scans and pen-testing to identify any additional vulnerabilities.
- Monitor logs for any unauthorized access attempts and set up intrusion detection mechanisms.
---

### Finding 3: **Unrestricted Sudo Access to Perl**
#### Identified Issue:
```bash
sudo /usr/bin/perl -e 'exec "/bin/sh"'
```

#### Observation:
- The binary /usr/bin/perl can be executed with sudo privileges without requiring a password.
- This unrestricted access allows trivial exploitation to gain elevated privileges, including obtaining a root shell.

#### Risk Rating:
- **Critical**: The lack of password protection for  access to  poses an immediate security risk. It enables privilege escalation, granting attackers root access to the system with minimal effort.

#### Recommendations:
- Immediately restrict sudo access to /usr/bin/perl by modifying the sudoers file.
- Audit and review sudo permissions across all users to ensure no unnecessary privileges are granted.
- Implement principle of least privilege (POLP) to minimize potential attack vectors.
- Regularly monitor system logs for signs of unauthorized sudo activity.
- Train administrators and users on secure privilege management practices.
---


## Conclusion
The penetration test uncovered significant security vulnerabilities that allowed attackers to escalate privileges and achieve full domain compromise. Key findings included exposed network services, vulnerable CGI scripts, and unrestricted sudo access to system binaries. Each of these weaknesses poses a critical risk to the host's security posture and highlights the importance of proactive measures to mitigate threats.
By implementing the recommendations provided, including restricting access, updating configurations, auditing permissions, and conducting regular security assessments, the host can significantly reduce its exposure to potential attacks. Strengthening access controls, enforcing secure coding practices, and maintaining a rigorous monitoring regime are essential steps towards enhancing the overall security of the system.
This engagement underscores the need for continuous vigilance and improvement in cybersecurity practices to safeguard against evolving threats. The insights gained from this assessment serve as an invaluable resource for strengthening defenses and improving resilience against future attacks.
