## 2. Incident Summary
An end user reported an urgent issue involving file inaccessibility within the designated S3 bucket `forela-fileshare`. Investigation revealed the S3 bucket was **misconfigured** with a **public access policy**, leading to unauthorized access by an external threat actor from IP `54.242.59.197`.

The threat actor exfiltrated a sensitive credentials file and escalated privileges by leveraging the stolen access keys. Multiple lateral discovery and privilege escalation attempts were made, culminating in admin-level access and persistence mechanisms being established within the environment.

## 6. Root Cause Analysis
The root cause of the incident was a **misconfigured bucket policy** on `forela-fileshare` that inadvertently allowed **public (anonymous) access**. The attacker exploited this misconfiguration to retrieve sensitive credentials and conduct privilege escalation using AWS IAM policies and access keys.

---

## 7. Mitigation & Response Actions

- [x] Immediately revoked all exposed access keys
- [x] Reconfigured S3 bucket policies to enforce least privilege
- [x] Implemented service control policies to block public S3 access
- [x] Isolated and audited IAM user `forela-admin` and `dev-policy-specialist`
- [x] Removed unauthorized policies and roles
- [x] Rotated KMS encryption keys
- [x] Enabled CloudTrail and GuardDuty alerts for anomalous activity

---

## 8. Recommendations

- Enforce **least-privilege policies** across all S3 buckets
- Use **S3 Block Public Access** settings organization-wide
- Enable **AWS Config rules** to audit bucket configurations
- Implement **automated remediation** for public bucket creation
- Regularly audit IAM users, policies, and keys
- Enable multi-factor authentication (MFA) on all accounts
- Deploy **SIEM alerting** on IAM policy changes and object access logs

---

## 9. Conclusion
A cloud infiltration incident occurred due to a public S3 bucket misconfiguration, resulting in the theft of 7 access keys and unauthorized privilege escalation. The incident was contained, persistence removed, and hardening actions implemented. No further malicious activity has been observed since containment.
